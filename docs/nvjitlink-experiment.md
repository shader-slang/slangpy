# Compare shared-library nvJitLink with standalone PTX compilation

This living ExecPlan follows .agents/PLANS.md and extends the committed cubin-cache-experiment.md. Work is in C:\projects\slangpy on dev/skallweit/parallel-compilation-experiment. The baseline commits are SlangPy 04a4bd50 and slang-rhi 733c99e0.

## Purpose

Determine whether NVIDIA's supported nvJitLink shared library can replace the static nvPTXCompiler dependency while retaining parallel compilation and persistent CUBIN caching. PTX is the assembly-like intermediate generated by Slang/NVRTC; CUBIN is native GPU code loaded by CUDA. Compare the same 24 kernels and validate outputs and cache behavior before interpreting timings.

## Context and Orientation

external/slang-rhi/src/cuda/cuda-cubin.cpp currently converts PTX in existing entry-point worker jobs, using one nvPTXCompiler handle per job. Its CubinArtifact retains PTX for rejected-cache recovery; cuda-pipeline.cpp loads the CUBIN and rebuilds a rejected cached image. persistentPipelineCache stores versioned, checksummed CUBIN records independently from the PTX shader cache. SGL already supplies both slots through its concurrent persistent cache. tools/benchmark_pipeline_compilation.py runs each sample in a fresh process and verifies outputs and wall traces. Tests are in slangpy/tests/device/test_cubin_cache.py and the native cuda-cubin-cache-recovery case.

## Decision Log

Use the public nvJitLink header and NVIDIA's import library/shared binary. Its public C++ inline functions reference versioned exported symbols; do not invent or scrape an internal entry-point interface. CMake will accept SLANG_RHI_NVJITLINK_ROOT and copy the selected Windows DLL into the runtime directory. This experiment uses ordinary shared linking, not a custom DLL bridge.

Keep nvPTXCompiler available as a comparison. SLANG_RHI_CUDA_CUBIN_COMPILER selects nvptxcompiler (existing default) or nvjitlink, snapshotted when creating a device. Each worker creates, adds PTX to, completes, and destroys its own nvJitLink handle. Use -no-cache to disable nvJitLink's intermediate cache and -split-compile=1 so this measures parallel independent programs. Include compiler kind, binary fingerprint, target, and all options in CUBIN keys. Keep Slang's cumulative timing counters out of every comparison.

Hash the actual loaded nvJitLink binary at device initialization using SHA1, and independently verify that fingerprint in Python. A configured-library hash is insufficient for a replaceable shared dependency. Cache keys move to namespace rhi-cuda-cubin-v2 and include the compiler kind and effective option vector; older experimental CUBIN entries become misses, while PTX cache entries remain usable.

## Surprises and Discoveries

The installed CUDA 12.2 header routes public calls such as nvJitLinkCreate through versioned __nvJitLinkCreate_12_2 exports. Matching public headers/import libraries avoids hardcoding this detail. NVIDIA's 12.9 documentation specifies a -no-cache option; leaving this enabled would confound the cold compilation comparison.

Downloaded libnvjitlink-windows-x86_64-12.9.86-archive.zip from NVIDIA's CUDA 12.9.1 manifest. Verified archive SHA256: ee7175da9628d47ccc92dce6d28d57ca77633e79079a2aee90e2a645edcd1384. NVIDIA's DLL is 87,359,488 bytes. This avoids the custom CRT-isolation wrapper, but still carries a substantial shared compiler binary.

The native Release build was configured with SLANG_RHI_NVPTXCOMPILER_ROOT empty and SLANG_RHI_NVJITLINK_ROOT pointing to the isolated package. dumpbin /dependents shows nvJitLink_120_0.dll and no nvPTXCompiler wrapper dependency. Both cuda-cubin-cache-recovery and the CUDA ray-tracing regression passed, including truncated/checksum-corrupt/driver-rejected entries and cache I/O errors.

The SlangPy Debug build includes both compiler alternatives for comparison. With SLANGPY_TEST_CUBIN_COMPILERS=nvptxcompiler,nvjitlink, the two subprocess integration cases pass, including backend changes, option changes, PTX changes, fresh-process reuse, and the plain driver-PTX path. With nvJitLink selected for CUDA, all 15 prepare/pending regressions pass across CUDA, D3D12, and Vulkan. The native build's 336 assertions also establish that nvJitLink works without linking the static compiler.

The current optional CMake integration is for the CUDA 12.9 experiment. It uses a regular runtime dependency on NVIDIA's shared DLL, not lazy loading; an enabled build requires that DLL even when another backend is selected. Production deployment and discovery can be refined separately. The shared DLL is fingerprinted at setup time, which is reported separately from compilation timing.

Cold nvJitLink parallel compilation is 4.83 times faster than its serial mode. Compared with the contemporary nvPTXCompiler parallel control, it reduces elapsed time by 12.0% (1.14 times faster). The previous session's driver-PTX-JIT parallel median was 67.665 seconds, versus 18.687 seconds here; that historical comparison is about 3.62 times faster, with the caveat that the measurements were taken in different sessions.

The serial nvJitLink median of the summed, non-overlapping PTX intervals is 41.931 seconds, CUBIN conversion 47.598 seconds, and pipeline loading 0.048 seconds. The contemporary single nvPTXCompiler serial control spends 43.768 seconds generating PTX, 61.777 seconds converting CUBIN, and 0.052 seconds loading pipelines. The improvement is consistent with faster CUBIN conversion, rather than a changed workload or a hidden cache hit.

For parallel nvJitLink, the median PTX wall envelope is 8.991 seconds, the CUBIN envelope 17.405 seconds, and pipeline loading 0.047 seconds. These stages overlap and must not be added. The median longest individual CUBIN job is 9.658 seconds, compared with 12.055 seconds for nvPTXCompiler. The former driver-JIT load bottleneck has disappeared; the remaining time is spent in concurrent PTX generation and CUBIN compilation. This does not establish ideal scaling or a thread-safety guarantee for all workloads.

All 23 full-workload samples have identical source hashes and exactly equal outputs to the committed nvPTXCompiler baseline. Every cold sample has zero PTX/CUBIN hits; every warm sample has 24 PTX and 24 CUBIN hits in a fresh process. Driver, NVRTC, and nvJitLink intermediate caches remain disabled. The four-mode small smoke run also passes with the final implementation. Python elapsed time is measured independently; raw RHI timestamps are used only for wall intervals. Setup is excluded: its median is about 2.18 seconds for cold nvJitLink parallel runs and 1.87 seconds for nvPTXCompiler, including device/module/tensor initialization and runtime compiler identification. GPU execution throughput and generated machine-code quality were not benchmarked.

## Outcomes and Retrospective

nvJitLink is a viable replacement for the static compiler in this experiment. It preserves parallel PTX-to-CUBIN conversion, persistent caching, error recovery, and output correctness while using NVIDIA's own shared library. It is modestly faster than the contemporary nvPTXCompiler control on this workload. The substantial improvement over driver PTX JIT comes from moving compilation into worker jobs and loading CUBIN afterward; the choice between the two standalone compilers is a smaller additional gain.

The remaining production work concerns library discovery/deployment, lazy loading if desired, and broader platform/version/workload coverage. NVIDIA's 87.4 MB DLL removes the custom wrapper requirement, but does not reduce the compiler binary footprint. No additional prepare/pending API changes were required. This work extends the experiment branches while preserving the earlier committed nvPTXCompiler baseline.

Final validation: both native configurations built successfully; two Python compiler/cache integration cases and 15 prepare/pending regression cases passed; the nvJitLink-only native build passed two cases with 336 assertions. Both repositories passed pre-commit run --all-files and git diff --check. New documentation and JSON reports were also checked explicitly, and the final formatted full-workload reports were revalidated against the baseline.
